# phase 01 — setup

JOB: leave exactly one ticket in progress with its run dir, branch, and unlock reasoning on the record
IN:  `.map/roadmap.json` (bootstrapped here on first run); no other ticket `in progress` unless this is a resume or take-over
OUT: roadmap.json status flips; `.gitignore` fences `.map/<PREFIX>-*/`; `.map/<ID>/state.json` created, untracked; branch `map/<ID>` checked out

## steps

1. bootstrap when roadmap.json is missing. Look for a connected task system: Linear MCP(Model Context Protocol) tools, `gh issue list`, TODO or BACKLOG files. Offer to import the found items as tickets, and let the user select which ones. Ask the user for the 2-4 letter prefix once, uppercase. Found nothing → ask the user to create the roadmap. HUMAN GATE either way. Done when roadmap.json parses with prefix + next_nnnn + tickets.
2. close out the past. Flip a `resolved` ticket to `done` when its `map/<ID>` branch reached the default branch. This step is a SAFETY NET, and it is not the primary path. Phase 23 flips the ticket the moment it merges on the local-squash route, which is what a repo with no remote uses; on the PR route this sweep is the flip. A squash merge is invisible to `git branch --merged`. The squashed commit is a fresh one, so the branch tip never becomes an ancestor of the default branch. The sweep then silently never fires. `git cherry` is no help either, because it matches patch ids per commit against one combined commit. So `git branch --merged` and `gh pr list --state merged` catch the true-merge path and the PR path. For anything still `resolved` whose branch those two miss, check tree parity instead: `git diff <default-branch> map/<ID> --stat` comes back empty when the content is already in. Ask the user before you flip when the parity is ambiguous, because the default branch has moved on. Done when no merged ticket is still resolved, and nothing was flipped on a guess.
3. pick the ticket. Run `skills/task-graph/scripts/next-ticket.sh .map/roadmap.json`. Accept the pick, or override it with a one-line reason stored in `state.json.next_override`. A needs-replan ticket has a cancelled dep. Take it to the user, and never auto-select it. Done when one ticket is chosen with its unlock count known.
4. fence the run dir off from git BEFORE it exists. `.gitignore` must carry `.map/<PREFIX>-*/`, using the roadmap's own prefix. Create `.gitignore` when the repo has none. Verify the fence with `git check-ignore -v .map/<ID>/state.json`. Verify that the repo-level map escapes it: `git check-ignore .map/roadmap.json` must find nothing. Untrack any ticket dir that an earlier run left tracked, with `git rm -r --cached .map/<PREFIX>-*`. The file count on disk stays identical before and after, because `--cached` touches the index only. Land that untracking as its own commit. Done when `git ls-files '.map/<PREFIX>-*'` is empty and the roadmap files are still tracked.
5. open the run. Set the ticket `in progress`. Create `.map/<ID>/` and state.json, with `phase: 1` and empty ledgers. Create or check out the branch `map/<ID>`. A take-over is a run where the branch exists and the map never ran. On a take-over, create the run dir, then follow the take-over entry point. Never re-initialize. Done when dir + branch + pointer exist.
6. HUMAN GATE A. Apply STANDING APPROVAL from SKILL.md over the chosen ticket, its unlock reasoning, and any override. Present that material only when the governing rule fires the gate. Invoke /show-me on that pick and its unlock picture. Ask for its smallest fitting view. Do not select its output format. Prefer a console-safe view. Commit `map(<ID>): phase 01 setup` with `--allow-empty`. The run dir is untracked, so nothing is staged unless step 4 changed `.gitignore`. Done when the user has seen the pick, `state.json.gates.A` records their verdict, and the commit exists.
