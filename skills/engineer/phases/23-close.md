# phase 23 — close

JOB: the diff conformant to the comment whitelist and code style, fresh-reviewed, statuses closed, the work landed by PR(Pull Request) when the project has a remote, or by local squash merge when it has none
IN:  state.json.gates.D recorded (phase 22's gate cleared), the full branch diff, docs/comment-style.md, docs/code-style.md, tasks.json, roadmap.json, signoff.md; phase 22 committed
OUT: clean diff, statuses updated, the work landed on the default branch as an open PR URL, or as a verified local squash merge in a repo with no remote

## steps

1. audit the comments. List every comment in `git diff <default-branch>...HEAD`. Only the four whitelisted shapes survive: inexpressible concept or architecture, standard-violation exception, deliberate TODO, and advanced math. Delete everything else, and make the code explain itself. Then sweep mechanically. Zero `TODO(<TICKET>` markers remain, and `git ls-files '.map/<PREFIX>-*'` comes back empty. No ticket run dir may reach a PR. Phase 01 fenced it, and this is the check that the fence held. It also catches a `git add -A` that widened past the paths a phase owned. Done when all three pass.
2. audit the style against docs/code-style.md, covering is-prefixed booleans and the rest. Apply the /simplify doctrine: small refactors, renames, and prunes only. Behavior changes are out of scope here. Done when the diff reads like the surrounding code.
3. audit the prose. Invoke /byline on the commit trail and on any README, changelog, or doc the branch touched. The PR body goes through it in step 7 before it is submitted. Facts stay verbatim through the pass. Done when `ste-check --register byline` returns zero FAIL lines on each edited piece.
4. [FRESH] dispatch code-reviewer with repo_path + diff_range = `<default-branch>...map/<ID>`. The dispatch must NOT carry this session's transcript, a self-summary, or ANY stash or checkout instruction, because repo modification by the reviewer is catastrophic in its own rubric. Criticals → fix and re-dispatch once. A second Critical round goes to the human. Done when the review returns no Criticals.
5. close the statuses. The tasks go to done in tasks.json. The ticket goes to `resolved` in roadmap.json. Resolved means reviewed and finished, `done` means landed, and step 7 is what flips it. On the PR route, which is the default wherever a remote exists, the next run's phase 01 does that flip after the merge. On the local-squash route step 7 flips it here, because phase 01's sweep is blind to a squash. Done when both files are updated.
6. HUMAN GATE E. The branch stays local until this gate clears, and nothing is pushed before it. Present the diff stat, the commit count, the target branch, the review verdict, and any finding accepted rather than fixed, with its reasoning. Invoke /show-me on that landing bundle. Ask for its smallest fitting view. Do not select its output format. Prefer a console-safe view. Then STOP. Rationale: the push is the run's first outward-facing act. It publishes the work, it triggers CI(continuous integration), and it notifies collaborators. /create-pr does not gate on its own: it stops only on an empty diff or on a rejected push. Everything before this phase is local and rewindable. This is not. Done when the human says push and `state.json.gates.E` records it. A push before this gate is the map's one unrecoverable act. Force-push is banned skill-wide, so a premature or wrong push cannot be retracted, only added to. If it happens, STOP, tell the user what reached the remote, and let them choose the remedy. Never quietly push and report the PR as though the gate had cleared.
7. land it. `git remote` decides the route, and the human confirms it at gate E: a project WITH a remote lands through a PR, which is the standing default from 2026-08-20 — the owner's words, "gate e will run through PR as is the new standard for git projects with a remote". A project with NO remote lands by local squash merge.
   - **PR** — the default when the project has a remote. Invoke /create-pr. It commits the pending work, pushes, and opens or updates the PR under its own hard rules: no attribution lines, and never force-push. The signoff.md bullets go into the PR body. Done when the PR URL is reported. A repo with no remote at all is not a create-pr failure to retry. It is a different question, meaning create the repo and publish, or merge locally, and it goes back to the human.
   - **local squash merge** — the route for a repo with NO remote. It was the standing default from 2026-08-07 ("merge locally into main (squash always)") until 2026-08-20, when the PR route replaced it wherever a remote exists. Verify tree parity after you commit the squash, with `git diff <default-branch> map/<ID> --stat` coming back empty. Rerun the suite on the default branch. Flip the ticket straight to `done` HERE rather than leaving it `resolved`, because phase 01's sweep cannot see a squash merge and a ticket left resolved stays resolved forever. Back up and count-verify anything the merge deletes from the default branch's working tree BEFORE the merge, then restore it after. Untracking a ticket run dir on the branch means the merge deletes those files from the default branch's checkout.

   The commit trail ends `map(<ID>): phase 23 close`.
