# agents fleet research — 2026-07-31

## findings, ranked by confidence

### high confidence — anthropic official

**definition anatomy.** A subagent is a Markdown file with YAML(YAML Ain't Markup Language) frontmatter; only `name` and `description` are required. Full supported field set: name, description, tools, disallowedTools, model, permissionMode, maxTurns, skills, mcpServers, hooks, memory, background, effort, isolation, color, initialPrompt. The body becomes the agent's ENTIRE system prompt — it does not get the Claude Code system prompt, just the body plus basic environment details. ([sub-agents docs](https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields), accessed 2026-07-31, v2.1.219 — anthropic official)

**scope and precedence.** Name collisions resolve: managed settings > `--agents` CLI(command-line interface) JSON(JavaScript Object Notation) flag > `.claude/agents/` project > `~/.claude/agents/` user > plugin. Directories scan recursively (identity is the `name` field, subfolders fine), nested project dirs resolve closest-to-cwd (v2.1.178+), names may not contain `:` (v2.1.218+ refuses to load), files hot-reload — except the first file in a brand-new agents/ dir, which needs a restart. ([sub-agents docs](https://code.claude.com/docs/en/sub-agents#choose-the-subagent-scope), accessed 2026-07-31 — anthropic official)

**description is the router.** Delegation matches the task against the `description` field plus context; official lever for auto-dispatch is phrasing like "use proactively". Escalation ladder: natural language → `@agent-<name>` (guaranteed dispatch, Claude still writes the task prompt) → `claude --agent <name>` / settings `"agent"` (whole session runs on that agent's prompt, tools, model). ([sub-agents docs](https://code.claude.com/docs/en/sub-agents#understand-automatic-delegation), accessed 2026-07-31 — anthropic official)

**model + effort dials.** `model` accepts sonnet/opus/haiku/fable, a full model ID, or `inherit` (default); resolution: CLAUDE_CODE_SUBAGENT_MODEL env var > per-invocation param > frontmatter > main model. `effort` (low/medium/high/xhigh/max) overrides session effort per agent. Extended thinking is inherited from the main conversation (v2.1.198+), no per-agent toggle. For Fable 5: `high` default, `xhigh` only for capability-sensitive work, `medium`/`low` for routine — lower effort on Fable 5 often exceeds xhigh on prior models. ([sub-agents docs](https://code.claude.com/docs/en/sub-agents#choose-a-model) + [fable 5 prompting](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5), accessed 2026-07-31 — anthropic official)

**tool grant semantics.** `tools` is an allowlist (omit = inherit everything), `disallowedTools` a denylist applied FIRST; both accept MCP(Model Context Protocol) server patterns (`mcp__<server>`, `mcp__<server>__*`). A `tools` list where no entry resolves refuses to launch (v2.1.208+ — misspellings hard-fail). Preload domain knowledge via the `skills` field (full content injected at startup), not by listing Skill in tools. `mcpServers` frontmatter scopes an inline MCP server to one agent so its tool descriptions never hit main context. ([sub-agents docs](https://code.claude.com/docs/en/sub-agents#available-tools), accessed 2026-07-31 — anthropic official)

**background is the default.** Since v2.1.198 subagents run in the background unless the result is needed immediately, with a reduced built-in tool set (Read, Grep, Glob, Bash, Edit, Write, WebFetch, WebSearch, TodoWrite, Skill, ToolSearch, SendMessage, Monitor, worktree tools, etc. plus all MCP tools); everything else is silently stripped, so one definition resolves to different tools foreground vs background. `background: true` forces always-background. AskUserQuestion and plan-mode tools are stripped from all subagents; permission prompts surface in the main session (v2.1.186+). Write agents assuming background. ([sub-agents docs](https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background), accessed 2026-07-31 — anthropic official)

**permissionMode.** Accepts default, acceptEdits, auto, dontAsk, bypassPermissions, plan, manual (v2.1.200+). Parent bypassPermissions/acceptEdits wins and can't be overridden; parent auto mode ignores the agent's frontmatter mode entirely. Plugin-distributed agents ignore hooks, mcpServers, AND permissionMode — packaging the fleet as a plugin silently drops all three. ([sub-agents docs](https://code.claude.com/docs/en/sub-agents#permission-modes), accessed 2026-07-31 — anthropic official)

**persistent memory is native.** `memory: user|project|local` gives a cross-session directory (`project` → `.claude/agent-memory/<name>/`, recommended default, git-shareable); first 200 lines / 25KB of its MEMORY.md is injected each run, Read/Write/Edit auto-enabled; docs advise an explicit "update your agent memory as you discover patterns" instruction in the body. Silently inert if auto memory is disabled. ([sub-agents docs](https://code.claude.com/docs/en/sub-agents#enable-persistent-memory), accessed 2026-07-31 — anthropic official)

**startup context and limits.** A subagent gets exactly: its system prompt + environment, the delegation message, the FULL CLAUDE.md hierarchy (so bodies need not repeat house rules), a git status snapshot, preloaded skills, and a sibling roster for SendMessage (v2.1.206+). Never: conversation history, output style, main-session auto memory. Limits: 3 nesting layers default, 200 spawns/session, 20 concurrent. Finished subagents are resumable with full history via SendMessage. ([sub-agents docs](https://code.claude.com/docs/en/sub-agents#what-loads-at-startup), accessed 2026-07-31 — anthropic official)

**official authoring prescriptions + exemplar fleet.** Four best practices: one task per agent, detailed descriptions, minimal tool grants, version-control the files. The docs demo a deliberately tiny fleet: code-reviewer (read-only Read/Grep/Glob/Bash, prompt starts "Run git diff", output ranked Critical/Warnings/Suggestions), debugger (adds Edit, 5-step root-cause workflow), data-scientist, plus a hook-gated validator. Built-in Explore/Plan/general-purpose already cover research/planning; prefer the main conversation when phases share context; prefer skills over agents for reusable recipes. Frontmatter `hooks` (PreToolUse exit-2 blocking) is the finer-than-tools control pattern (project-level hooks gated behind workspace trust, v2.1.218). The /agents wizard was removed in v2.1.198 — author by editing files directly. ([sub-agents docs](https://code.claude.com/docs/en/sub-agents#example-subagents), accessed 2026-07-31 — anthropic official)

**delegation threshold.** "Ten or more files, or three or more independent pieces of work" is the signal to delegate. Four cases where subagents HURT: sequential dependencies, parallel edits to the same files, small tasks, agent proliferation — "most teams settle on a handful of well-scoped agents rather than a sprawling roster." Subagents can't talk to each other mid-flight; they report back to main. ([subagents in claude code](https://claude.com/blog/subagents-in-claude-code), 2026-04-07 — anthropic official)

**when multi-agent is justified at all.** Multi-agent costs 3-10x tokens; justified only by context protection (subtask emits >1000 tokens of noise), parallelization of independent work, or specialization (an agent juggling 15-20+ tools starts failing at tool selection). Named failure modes: handoff "telephone game", problem-centric decomposition (split by work type instead of context boundaries), and "early victory" verifiers that pass work without testing it. Start simplest, add agents only on evidence. ([when to use multi-agent systems](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them), 2026-01-23 — anthropic official)

**multi-agent numbers + delegation contract.** Orchestrator + subagents beat single-agent Opus by 90.2% on breadth-first research but burns ~15x chat tokens (token spend explained 80% of variance); "most coding tasks involve fewer truly parallelizable tasks than research." Effort-scaling to embed in any dispatcher prompt: simple fact-finding = 1 agent, 3-10 tool calls; comparisons = 2-4 agents, 10-15 calls each; complex research = 10+. Every dispatch needs: objective, output format, tool/source guidance, task boundaries — vague dispatches caused duplicated work and gaps. ([multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system), 2025-06-13 — anthropic official)

**context engineering.** Three long-horizon techniques and when each applies: compaction (extensive back-and-forth), structured note-taking (iterative milestones), subagents (parallel exploration) — each subagent returning a condensed 1,000-2,000-token summary. System prompts at the "right altitude" between brittle hardcoded logic and vague guidance, organized into distinct sections (`<background_information>`, `<instructions>`, `## Tool guidance`, `## Output description`), targeting "the minimal set of information that fully outlines your expected behavior" (minimal ≠ short). Hold lightweight identifiers, retrieve just-in-time. ([effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), 2025-09-29 — anthropic official; note: the widely repeated "3-5 examples" count is NOT in this source — it says only "diverse, canonical examples")

**agent loop + verification ranking.** The loop is gather context → take action → verify work → repeat; subagents serve exactly two purposes: parallelization and context isolation. Verification mechanisms in preference order: rules-based (tests/linters/validators) > visual (screenshots) > LLM(large language model)-as-judge (least robust). Underperformance diagnostics: missing information? restructure search/APIs? formal rules for repeated failures? different tools? ([building agents with the claude agent SDK](https://claude.com/blog/building-agents-with-the-claude-agent-sdk), 2025-09-29 — anthropic official)

**tool design.** Consolidate granular tools into workflow-level ones; namespace by service/resource; return semantic identifiers not UUIDs(universally unique identifiers); Claude Code truncates tool responses at 25,000 tokens; iterate tool descriptions against evals — small refinements yield dramatic improvements. Few consolidated high-signal tools per agent beats broad inheritance. ([writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents), 2025-09-11 — anthropic official)

**evals.** 20-50 simple tasks drawn from real failures; a good task is one two domain experts would grade identically; grade outcomes/final state, not trajectories; pass@k where one success matters, pass^k where consistency matters (75% per-trial = ~42% pass^3); clean isolated environments; calibrate LLM judges against human verdicts with an "Unknown" escape; run as CI(continuous integration), keep regression suites at ~100%; reading transcripts is non-negotiable — plateaus usually mean a broken task. ([demystifying evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents), 2026-01-09 — anthropic official)

**long-running work.** Two-phase harness: initializer sets up init.sh + progress log + initial commit; per-session coder reads git log + progress, picks ONE unfinished feature, works only on it, commits descriptively, leaves clean. Feature list lives in JSON (models are less likely to inappropriately rewrite JSON than Markdown), all initialized failing; passing only after end-to-end testing "as a human user would." ([effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents), 2025-11-26 — anthropic official)

**workflows vs agents (dated but canonical).** Find the simplest solution: predefined workflows (prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer) for predictable tasks; true agents only for open-ended problems where step count is unpredictable. Evaluator-optimizer only with clear criteria and measurable refinement value. ([building effective agents](https://www.anthropic.com/engineering/building-effective-agents), 2024-12-19 — anthropic official)

**fable 5 prompting.** Copy-paste blocks: progress-grounding ("audit each claim against a tool result from this session" — nearly eliminated fabricated status reports) and anti-stall for autonomous pipelines ("if your last paragraph is a plan… do that work now"). "Separate, fresh-context verifier subagents tend to outperform self-critique." Prompts written for prior models are often too prescriptive for Fable 5 and degrade output — strip old instructions where default behavior is better. Never instruct the model to echo its reasoning. ([prompting claude fable 5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5), accessed 2026-07-31 — anthropic official)

**trigger-description craft (from skill docs, transfers to agent descriptions).** Third person always (injected into the system prompt; "I can help you…" breaks discovery); state what it does AND concrete trigger terms; max 1,024 chars; body under 500 lines with one-level progressive disclosure; create evals BEFORE writing documentation — three scenarios, baseline without the artifact, write minimal instructions to close the measured gap. ([skill best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices), accessed 2026-07-31 — anthropic official)

**native observability.** SubagentStart/SubagentStop hooks match on agent `name`; full per-run transcripts persist ~30 days at `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl` including compact_boundary preTokens. Current models over-delegate ("may spawn where a direct grep is faster"); Anthropic's damping block: use subagents for parallel/isolated/independent work, "for simple tasks… work directly rather than delegating." ([sub-agents docs](https://code.claude.com/docs/en/sub-agents) + [prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices), accessed 2026-07-31 — anthropic official)

### high confidence — practitioner

**abandonment case.** ksred shipped a specialized role fleet whose files "sat there gathering dust"; converged on 2-3 parallel read-heavy explorers plus one read-only code-reviewer. Measured 4-7x token multiplier; found description-based auto-routing unreliable (explicit invocation required); verdict: subagents "for read-heavy research and exploration, not parallel coding." ([ksred](https://www.ksred.com/claude-code-agents-and-subagents-what-they-actually-unlock/), 2026-03-16)

**stars ≠ value.** wshobson/agents ships 203 agents (38.4k stars), VoltAgent advertises "100+ subagents" — while every substantive usage writeup found (Anthropic docs, ksred, sankalp, HumanLayer) runs 0-5 custom agents. No dated writeup demonstrates value from a 100+ agent pack. ([wshobson/agents](https://github.com/wshobson/agents), stats accessed 2026-07-31)

### medium confidence

**the zero-agent null hypothesis.** Power user sankalp runs no custom subagents: built-in Explore plus occasional background agents suffices; many parallel subagents trigger a flickering bug; steering judgment beats configuration depth. Every authored agent must demonstrably beat this baseline. ([sankalp](https://sankalp.bearblog.dev/my-experience-with-claude-code-20-and-how-to-get-better-at-using-coding-agents/), 2025-12-27)

### low confidence (core verified, framing caveated)

**subagents are context control, not roles.** HumanLayer: "Subagents are not about playing house and anthropomorphizing roles. Subagents are about context control" — used only in the research step as fresh-context find/search/summarize workers so the parent never fills with Glob/Grep/Read output. Caveat: the "~40% utilization dumb zone" figure is NOT in the cited source (the doc gives 40-60% as a target range) and rests on unverifiable talk material. ([humanlayer ace-fca](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md), 2025-08)

**one guide's role table (not a consensus).** Tembo prescribes code-reviewer/debugger/test-writer on Sonnet, security-auditor on Opus, doc-maintainer on Haiku, read-only Read/Grep/Glob for reviewer and auditor, "context-isolation primitive, not a magic productivity wand," reviewer-first build order. Caveat: this is a single source; the "cross-guide consensus" framing is unsupported, and planner/researcher roles conflict with the official built-in Explore/Plan guidance. ([tembo](https://www.tembo.io/blog/claude-code-subagents), 2026-05-15)

## constraints from the house rules

All from this repo, 2026-07-31: `skills/agent-author/SKILL.md`, `skills/ai-author/SKILL.md`, `docs/reset-spec.md`, `CLAUDE.md`.

- [ ] should-it-exist tree runs FIRST, in order, stop at first match: existing artifact owns it → update; one-off/Q&A(question and answer) → nothing; linear recipe → skill; distinct role with own context/tools/judgment → agent; fan-out/loop/generate-judge → workflow. One-sentence justification or don't author. (ai-author)
- [ ] name is a kebab-case ROLE, one job — "if it needs an 'and', it is two agents." (agent-author)
- [ ] description states use-when AND skip-when; the dispatcher reads only the description, never the body. (agent-author)
- [ ] tools is a minimal named allowlist, start read-only, add only on eval-run proof; `tools: "*"` requires a written reason. (agent-author)
- [ ] model chosen by task shape: haiku for mechanical transform, sonnet for bounded build/research with a checkable pass signal, opus only where judgment lives — "Opus everywhere is habit, not a decision." (agent-author)
- [ ] body opens with the three-block protocol: input contract (inputs passed in, never assumed; missing input reported by name, never guessed), output contract (fixed shape, verbose within it), context discipline (NAME what the agent must not receive — "an exclusion you don't write down is one the dispatcher will violate"). (agent-author)
- [ ] embedded contract sections: trigger conditions with near-misses (out-of-trigger → say so and STOP), a dispatcher-checkable success rubric (file:line + repro command, never "did a good job"), a 3-5 item failure-mode watch-list (symptom + catching check). (agent-author)
- [ ] designed against the four killers: role creep, context bloat, self-verification (worker and checker never share a context; cut any "review your work" step from builders), tool over-grant ("a checker with Edit will fix instead of grade"). (agent-author)
- [ ] ships evals/ (cases.jsonl, rubric.md, run.sh, holdout gating) with at least one out-of-trigger case (expect: declines) and one missing-input case (expect: reports gap by name); rubric grades anchors — real output, real runs, a diff on disk — never self-report. "No harness = not done." (agent-author)
- [ ] carries no logging section — usage evidence is derived from real Pi session transcripts by `tools/gepa-due`, never self-reported. (agent-author)
- [ ] full artifact contract: definition + evals/ (with frontier.jsonl/frontier/) + votes/votes.jsonl written ONLY by scripts/submit_vote.py; live only when non-holdout cases pass and holdout holds. (ai-author)
- [ ] blind fresh-context judge, dispatched only from gepa-due's Reflect-time low-vote_count sampling: sees ONLY the artifact source + the real transcript excerpt around the sampled use — never votes/, never other transcripts; submits only via submit_vote.py. (ai-author)
- [ ] evolution only through the GEPA(Genetic-Pareto prompt evolution) loop: small named single-concern mutations, accept only on harness win, ties to incumbent; the mutation-proposer never writes eval cases, rubric, or votes — "the exam stays out of the student's hands." (ai-author)
- [ ] agents/ is empty by design; every agent authored fresh — the old ~13-agent fleet's content must not be ported ("no embedded contract, no eval… do not port that content"). (reset-spec)
- [ ] router / model-selector / prompt-engineer advisory pipeline: dismissed 2026-07-30, deleted 2026-07-31 — any lookalike must cite the dismissal, not get re-authored. (reset-spec, auto-memory)
- [ ] structural rules: no hooks or paths into ~/swarm or ~/swarm-skills; no forced-dispatch regimes; install.sh symlinks-only; single canonical skills root; rollback is git history only. (reset-spec)
- [ ] mouthpiece stays a SKILL — do not re-author end-user voice as an agent; evals stay unseeded unless explicitly told to seed. (reset-spec)
- [ ] comms rules encoded in every contract: quoted content passes through unaltered; verbose between agents within the shape; each dispatch carries only what its step needs; expand every abbreviation at first use; simplest thing that ships, no speculative abstraction. (CLAUDE.md)

## candidate agent shapes — HUMAN GATE

No agent below gets authored until the user approves its shape. This list is candidates, not decisions.

Fleet size target from the evidence: a handful (official "handful, not roster", 2026-04-07; real-writeup ceiling ~5, ksred/sankalp; null hypothesis is zero).

**1. code-reviewer**
- one sentence: reads a diff with fresh context and returns ranked findings anchored to file:line plus a repro command, checkable by the dispatcher without redoing the review.
- support: official exemplar + four best practices ([docs](https://code.claude.com/docs/en/sub-agents), 2026-07-31); context-protection + anti-"early victory" contract need ([blog](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them), 2026-01-23); the one role that survived ksred's teardown (2026-03-16) and tembo's reviewer-first order (2026-05-15, low).
- must NOT be: granted Edit/Write (a checker with Edit fixes instead of grading); a fixer ("verify it and fix what you find" is two agents); a self-check step inside a builder's context.

**2. web-research-summarizer**
- one sentence: fans out over external docs and web sources with fresh context and returns a 1,000-2,000-token cited findings block so the parent never ingests raw pages.
- support: breadth-first is where multi-agent pays, with the four-part dispatch contract ([multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system), 2025-06-13); 1-2k condensed summaries ([context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), 2025-09-29); context-control thesis ([humanlayer](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md), 2025-08, low).
- must NOT be: a repo explorer (built-in Explore owns codebase search per the official docs — authoring a sibling fails the tree); dispatched for simple fact-finding (1 agent / 3-10 calls rule); a file writer.

**3. debugger**
- one sentence: takes a named failing repro, root-causes it, applies a minimal fix, and reports cause + diff + the command that proves the fix.
- support: official exemplar — the one role that justifies adding Edit ([docs](https://code.claude.com/docs/en/sub-agents), 2026-07-31); the verify step wants rules-based feedback with concrete failure output ([agent SDK](https://claude.com/blog/building-agents-with-the-claude-agent-sdk), 2025-09-29).
- must NOT be: also the reviewer or test-writer (role creep); its own verifier — a fresh checker grades the fix ([fable 5 prompting](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5), 2026-07-31).

**4. anchor-verifier**
- one sentence: fresh-context checker that runs the dispatch's named verification command against a worker's output and grades the rubric on anchors, never on the worker's self-report.
- support: "separate, fresh-context verifier subagents tend to outperform self-critique" ([fable 5 prompting](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5), 2026-07-31); rules-based > judge ranking ([agent SDK](https://claude.com/blog/building-agents-with-the-claude-agent-sdk), 2025-09-29); the "early victory" failure mode demands explicit really-test-it contract language ([blog](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them), 2026-01-23).
- must NOT be: ai-author's blind vote judge (that capability exists — this one verifies work products against a dispatch rubric, not artifact quality over time; if the gate finds the overlap with code-reviewer too large, merge or drop); granted Edit; ever sharing the worker's context.

**struck: dispatcher / model-router / prompt-optimizer.** Any agent that routes tasks to agents, selects models, or rewrites prompts before dispatch resembles the router/model-selector/prompt-engineer advisory pipeline dismissed 2026-07-30 and deleted 2026-07-31 (docs/reset-spec.md; pinned in auto-memory "cite this if attempted"). Struck. The harness already owns each function: routing is the description field, model choice is frontmatter, prompt craft belongs to the author skills.

**not proposed: planner / repo-researcher.** Built-in Explore and Plan cover these per the official docs, and the zero-agent null hypothesis (sankalp, 2025-12-27) says a custom one must prove it beats them via the eval harness first.

## not found / open questions

- **the ~40% context "dumb zone" threshold is unsourced.** The cited HumanLayer doc gives 40-60% utilization as a target range, not a degradation cliff; the companion talk carrying the claim is unverifiable. Do not cite the figure.
- **no evidence that 100+ agent packs deliver value** — but this is absence of writeups, not a measured negative. Star counts measure listicle appeal.
- **the "3-5 canonical few-shot examples" count is invented.** Anthropic's context-engineering post says only "diverse, canonical examples," no number.
- **no cross-guide consensus role list exists as cited.** The "recurring 2026 roles" claim rests on Tembo alone; treat its table as one guide's opinion.
- **`isolation`, `maxTurns`, `color`, `initialPrompt` semantics were not detailed** by any finding — verify against live docs before using them in a definition.
- **whether any custom agent beats built-in Explore/Plan plus a steered main session** is unmeasured; per house rules it is decidable only by each candidate's eval harness, which is also how the sankalp null hypothesis gets falsified or confirmed per agent.
- **auto-delegation reliability on Fable 5 is unmeasured**: official docs say the description drives it, ksred found it unreliable and invoked explicitly. Whether "use proactively" phrasing suffices needs eval evidence; until then, workflows should invoke agents explicitly.
- **no official per-subagent token budget or cost-cap mechanism was found** beyond the `effort` field and prompt-level effort-scaling rules.
